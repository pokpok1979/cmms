# AGE CMMS Phase 4 — คลังอะไหล่
ส่งมอบ 23 ตุลาคม 2569

## ขอบเขต
- Master อะไหล่: รหัส/ชื่อ/หน่วย/จุดจัดเก็บ/บริษัท/สถานที่/จุดสั่งซื้อ/ใช้งานหรือระงับ
- รับเข้า เบิกใช้กับใบงานซ่อม และคืนโดยอ้างอิงรายการเบิก
- ยอดคงเหลือปัจจุบัน มูลค่าสต็อกถัวเฉลี่ยเคลื่อนที่ และรายการต่ำกว่าหรือเท่าจุดสั่งซื้อ
- แยกต้นทุนอะไหล่สุทธิตามใบงานจากค่าใช้จ่ายเดิมของ Phase 1
- ประวัติรายการ Audit Log และ Excel .xlsx ของยอดคงเหลือ/ประวัติ/ต้นทุนใบงาน
- ป้องกัน stock ติดลบ คืนเกินรายการเบิก และบันทึกซ้ำด้วย idempotency key

## ติดตั้ง
ต้องมี Phase 1 + 2 + 3 จากบทสนทนานี้ (custom cmms_session) และ dependencies เดิม
หยุดเว็บ สำรองโค้ดและ MongoDB ก่อน แตก ZIP นอกโฟลเดอร์ cmms เช่น C:\CMMS_Phase4
เปิด Terminal ในโฟลเดอร์ cmms:

```powershell
node C:\CMMS_Phase4\install.cjs .
node --import tsx scripts/setup-inventory.ts
npm run typecheck
npm test
npm run build
npm run dev
```

Login แล้วเปิด http://localhost:3000/inventory (ปรับ host/port ตามที่ใช้จริง)
เพิ่มลิงก์ /inventory ใน sidebar เดิมได้ด้วยตนเอง

ตัวติดตั้งเพิ่มไฟล์เท่านั้น ไม่เขียนทับ Login/Users/PM/หน้าใบงาน/การเชื่อมต่อ DB หรือ package.json
พบไฟล์ชื่อเดียวกันที่แก้ไขต่างจากชุดนี้จะหยุดก่อนคัดลอก ติดตั้งซ้ำได้เมื่อไฟล์ตรงกัน
setup สร้าง indexes และ collection ใหม่ ไม่เรียก collMod ไม่ reset user/password ไม่ seed ยอดสต็อก
ต้องรัน setup สำเร็จก่อนทำรายการ โดยเฉพาะ unique index รหัสอะไหล่
Atlas ต้องรองรับ transactions และอนุญาต IP ของเครื่อง/server
APP_URL ต้องตรง origin ของเว็บ ไม่มีการเพิ่ม scheduler สำหรับคลัง

## สิทธิ์
| บทบาท | สิทธิ์ |
|---|---|
| Admin / Supervisor | เพิ่ม/แก้ master, รับเข้า, เบิกเข้าใบงานที่กำลังดำเนินการ, คืน และดูรายงานในพื้นที่ที่มีสิทธิ์ |
| Technician | ดูยอดคงเหลือ, เบิกเฉพาะใบงานที่ตนได้รับมอบหมายและอยู่สถานะ accepted/in_progress/waiting_parts/waiting_contractor, คืนจากรายการที่ตนเบิกขณะใบงานยังอยู่สถานะเหล่านี้ |
| Executive | ดูยอด/ประวัติ/ต้นทุน/ส่งออกในพื้นที่ที่มีสิทธิ์ อ่านอย่างเดียว |
| Requester | ไม่มีสิทธิ์เข้าคลัง |

ช่างเห็นประวัติการทำรายการของตน และต้นทุนของใบงานที่ตนได้รับมอบหมาย
ทุก API ตรวจคู่ companyId + siteId ห้ามเบิกข้ามพื้นที่ของอะไหล่กับใบงาน
Admin/Supervisor คืนอะไหล่จากใบงานที่ปิด/ยกเลิกแล้วได้เพื่อแก้ไขต้นทุน ต้องระบุเหตุผล และมี Audit

## เริ่มใช้งาน
1. เพิ่ม master อะไหล่ เลือกสถานที่ หน่วยนับ และจุดจัดเก็บ
2. ยอดเริ่มต้นเป็นศูนย์ รับเข้าพร้อมจำนวน/ราคาต่อหน่วย หากเป็นยอดยกมาให้ระบุในเลขอ้างอิง
3. อนุมัติใบแจ้งซ่อม มอบหมายช่าง และรับงานตาม Phase 1 ก่อน จึงเบิกอะไหล่ได้
4. เบิกจากหน้าคลัง เลือกใบงานสถานที่เดียวกับอะไหล่ ระบบตัด stock และเพิ่ม partsCostSatang ในใบงานอย่างเป็น transaction เดียว
5. คืนโดยเลือกรายการเบิกต้นทาง ระบบลดต้นทุนใบงานและนำกลับเข้าคลัง ไม่คืนเกินจำนวนที่ยังไม่คืน
6. ดูแท็บต้นทุนตามใบงานเพื่อดูค่าใช้จ่ายเดิม อะไหล่สุทธิ และยอดรวม

ข้อมูลใหม่ใช้ collections inventoryParts / inventoryMovements เพื่อไม่ชนกับ spareParts ที่สงวนไว้เดิม
หน้ารายละเอียดใบงาน Phase 1 ไม่ถูกแก้โดยชุดนี้ ให้ดูต้นทุนอะไหล่จาก /inventory แท็บต้นทุนตามใบงาน

## จำนวนและต้นทุน
- จำนวนรองรับทศนิยม 3 ตำแหน่ง จัดเก็บเป็นจำนวนเต็มหนึ่งส่วนพัน (qtyMilli)
- ราคาต่อหน่วยรับทศนิยม 2 ตำแหน่ง หน่วยบาท; มูลค่าเก็บจำนวนเต็มสตางค์
- รับเข้า: จำนวน × ราคาต่อหน่วย ปัดเป็นสตางค์หนึ่งครั้งต่อรายการ
- เบิก: เฉลี่ยจากมูลค่าสต็อกทั้งหมด/จำนวนคงเหลือ ณ เวลาบันทึก ถ้าเบิกหมดจะตัดมูลค่าที่เหลือทั้งหมด ไม่ทิ้งเศษสตางค์
- คืน: ใช้มูลค่าจากรายการเบิกเดิม ไม่ใช้ราคาปัจจุบัน การคืนบางส่วนปัดแบบสะสม และคืนครบจะคืนมูลค่ารายการเดิมครบ
- partsCostSatang แยกจาก costSatang เดิม ยอดรวมรายงาน = costSatang + partsCostSatang
- อย่าบันทึกค่าอะไหล่รายการเดียวกันซ้ำในค่าใช้จ่ายเดิมของ Phase 1 เพราะจะทำให้ยอดรวมซ้ำ
- จำนวนต่อรายการ/ยอดคงเหลือสูงสุด 1,000,000 หน่วย มูลค่าคลังต่ออะไหล่สูงสุด 90,000,000,000 บาท
- แต่ละรหัสมีหน่วยฐานเดียวและจุดจัดเก็บข้อความเดียว ไม่รองรับหลาย bin แยกยอดหรือแปลงหน่วย
- รหัส/บริษัท/สถานที่เปลี่ยนไม่ได้ หน่วยเปลี่ยนไม่ได้เมื่อมีการเคลื่อนไหว

## จุดสั่งซื้อและแจ้งเตือน
หน้าคลังแสดงอะไหล่ที่ใช้งานและ qty <= reorderPoint รวมกรณีคงเหลือศูนย์
เมื่อทำรายการแล้วเข้าเกณฑ์ต่ำเป็นครั้งแรก จะแจ้ง Admin/Supervisor ที่ active และมีสิทธิ์พื้นที่นั้น สูงสุด 100 บัญชี หากไม่มีจะส่งผู้ทำรายการ
ไม่ส่งซ้ำขณะยังต่ำ เมื่อรับกลับเหนือจุดสั่งซื้อแล้วจึงเปิดให้แจ้งรอบใหม่
การแก้ master หรือเพิ่มอะไหล่ยอดศูนย์แสดงเตือนใน dashboard ทันที แต่ไม่ได้ส่ง notification จนกว่าจะเกิดรายการเคลื่อนไหว
ไม่มี Email/Teams/LINE หรือการสร้างใบสั่งซื้ออัตโนมัติ

## รายงาน
- Stock: ยอดปัจจุบัน ไม่ใช่สต็อกย้อนหลัง ณ วันที่
- ประวัติ: กรองวันที่ทำรายการตาม Asia/Bangkok ไม่เกิน 366 วัน ค่าเริ่มต้น 30 วันล่าสุด
- ต้นทุนใบงาน: สุทธิตลอดอายุงาน ไม่กรองด้วยวันที่ประวัติ
- แบ่งหน้าละ 30 รายการ; Excel ส่งออกทุกหน้าตามตัวกรอง สูงสุด 10,000 รายการ
- Lookup แสดงสถานที่/อะไหล่/ใบงานและรายการเบิกคืนได้สูงสุดอย่างละ 1,000 รายการ

## ข้อจำกัด / การแก้ไขรายการ
- รายการบันทึกแล้วแก้หรือลบไม่ได้ การเบิกผิดแก้ด้วยการคืนอ้างอิงรายการเดิม
- ยังไม่มี reversal รับเข้าผิด, ปรับยอดตรวจนับ, โอนคลัง, ใบซื้อ, อนุมัติเบิกหลายขั้น, lot/serial/expiry, จองอะไหล่ หรือเชื่อม D365BC
- เบิกและคืนเชื่อม workOrders งานซ่อม Phase 1; งาน PM ใน pmOccurrences ยังไม่รองรับเบิกตรง ให้สร้างใบแจ้งซ่อมและ WO ก่อน
- ยังไม่ได้ทดสอบ Atlas จริง ความขัดแย้งพร้อมกัน หรือหน้าจอบนอุปกรณ์จริง อ่าน UAT_TH.md ก่อนใช้ Production
